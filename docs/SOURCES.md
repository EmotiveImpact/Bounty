# Source register and operator setup

Start on Node 24 with `npm ci`. Copy `.env.example` to `.env` if using partner credentials. Start with `npm run dev`. Research imports run separately from the API. Reload Research after importing. No provider key is required for the local planner or public observations. Configure secrets on the server only.

Manual sales input is a JSON array. Each record needs a stable unique transaction reference, title, exact variant, barcode, soldDate (YYYY-MM-DD), currency GBP and positive integer totalPence including buyer-paid postage. Importing the same reference updates the record. These are self-reported research records, not independently verified or automatically promoted to buy alerts.

For repeatable local scheduling, run `npm run worker:loop` in a separate process. The first run starts immediately; subsequent runs wait six hours after completion. Failed imports are logged and retried the next cycle. Use a process supervisor for restart after a host reboot. Credentialed research is on demand to control cost. Research snapshots show latest imported details per source record; Keepa series use a distinct ID per time point.

In Research, choose a barcoded acquisition offer, select the reported sold variants you have checked, and enter your expected costs and time. The calculator uses the lower median buyer-paid total and shows contribution and earnings per active hour. No match leaves the estimate empty. This operator-led research view is separate from the simulated Leeds planner.
